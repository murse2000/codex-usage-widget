# Codex 사용량 위젯

`CodexUsageWidget.exe`를 실행하면 화면 위에 고정된 작은 창이 열립니다. Codex app-server에 현재 로그인된 계정의 한도를 조회해 남은 비율(100%에서 사용량만큼 감소), 현지 리셋 시각, 남은 일·시간을 표시하고, 3분마다 자동 갱신합니다. `새로고침` 버튼으로 즉시 갱신할 수도 있습니다. 헤더의 반투명 원형 버튼을 눌러 투명도를 45~100%로 조절할 수 있습니다.

헤더의 반투명 원형 버튼을 열고 `윈도우 시작 시 자동 실행`을 선택하면 현재 Windows 사용자 계정의 Run 레지스트리에 실행 파일 경로를 등록합니다. 다른 PC에서도 파일을 복사한 뒤 위젯을 실행하고 이 항목을 선택하면 해당 PC의 경로로 등록됩니다. 위젯을 실행하려면 .NET 8 Desktop Runtime과 Codex CLI가 설치되어 있고 ChatGPT 계정으로 로그인되어 있어야 합니다.

창을 드래그해서 옮긴 위치, 표시 모니터, 투명도를 저장하고 재실행 시 복원합니다. 설정은 `%LOCALAPPDATA%\CodexUsageWidget\settings.json`에 저장합니다. 선택한 모니터가 연결되어 있지 않으면 주 모니터의 화면 안으로 복원합니다.

잔여량이 30% 이상이면 초록색, 30% 미만이면 노란색, 10% 미만이면 빨간색으로 표시합니다. 각 한도가 30% 또는 10% 미만이 되면 트레이 알림을 보냅니다. 동일한 초기화 주기와 단계에는 재실행해도 반복해서 알리지 않으며, 한 번에 10% 미만으로 내려가면 10% 알림만 보냅니다. 알림 표시 여부는 Windows 알림 설정의 영향을 받습니다.

위젯과 설정 창은 작업표시줄에 표시되지 않습니다. 트레이 아이콘을 우클릭하면 숨기기/보이기, 새로고침, 투명도/자동 실행 설정, 표시 모니터 선택, 종료 메뉴를 사용할 수 있습니다. 트레이 아이콘을 더블클릭하면 위젯을 숨기거나 다시 표시합니다. 제목줄의 닫기 버튼은 위젯을 숨기며, 프로그램을 종료하려면 트레이 메뉴의 `종료`를 선택합니다.

트레이의 `Tibo 리셋 예고`에서 예고 알림을 켜고 끄거나 최근 예고의 X 원문을 열 수 있습니다. 알림은 기본으로 켜져 있으며, [Codex Resets](https://codex-resets.com/)의 [공개 API](https://codex-resets.com/api/docs)를 2분마다 확인합니다. X API 키나 별도 로그인이 필요하지 않습니다. 개인 계정의 사용량·인증 정보는 이 서비스로 전송하지 않습니다.

공개 API의 `scheduled_reset` 중 Tibo(`@thsottiaux`)의 원문 링크가 확인되는 예고만 알립니다. 예측·관찰(`active_watch`)과 이미 완료된 리셋 기록은 알림 대상에서 제외합니다. 현재 등록된 유효한 예고는 첫 실행에서도 한 번 알리고, 같은 본문·참고 기한의 알림 이력을 설정 파일에 저장해 재실행이나 자료 재등장으로 반복 알림이 나오지 않게 합니다. 본문이나 참고 기한이 바뀌면 새 알림으로 구분합니다. 참고 기한이 지난 예고는 원문만 확인할 수 있고, 완료됐다고 표시하지 않습니다.

데이터 제공: Codex Resets — OpenAI와 별개인 커뮤니티 서비스입니다. 공개 자료 반영 지연이나 분류 오류가 있을 수 있어 X 실시간 알림이나 개인 계정 리셋을 보장하지 않습니다. 자료가 15분 이상 오래됐거나 조회에 실패하면 트레이에 확인 실패·갱신 지연을 표시합니다. Windows 알림 설정에 따라 알림이 표시되지 않을 수 있습니다.

Codex CLI의 app-server 프로토콜을 사용합니다. 별도의 비밀번호나 API 키를 저장하지 않습니다.

앱 업데이트는 시작 시와 6시간마다 [GitHub 최신 정식 릴리스](https://github.com/murse2000/codex-usage-widget/releases/latest)를 확인합니다. 트레이의 `앱 업데이트 → 업데이트 확인`으로 직접 확인할 수도 있습니다. 새 버전이 있으면 설치 여부를 묻고, `예`를 선택했을 때만 다운로드합니다. `아니요`를 선택한 버전은 자동으로 다시 묻지 않으며, 수동 확인에서는 다시 선택할 수 있습니다. 확인 실패는 트레이에 표시하고, 수동 확인이나 동의 후 다운로드·설치가 실패하면 오류 안내를 표시합니다.

저장소가 **비공개**이므로 자동 업데이트를 사용할 각 PC에 GitHub CLI(`gh`)를 설치하고 `gh auth login --hostname github.com`으로 저장소에 접근할 수 있는 계정에 로그인해야 합니다. 배포 파일에 GitHub 토큰을 포함하지 않으며, 위젯이 토큰을 추출하거나 별도 저장하지 않습니다. GitHub CLI가 없거나 접근 권한이 없으면 기존 위젯 기능은 그대로 사용할 수 있지만 업데이트는 확인할 수 없습니다.

업데이트 ZIP의 SHA-256을 GitHub 릴리스 메타데이터와 대조한 뒤, 압축 내부의 실행 파일 이름·버전을 확인합니다. 설치 준비가 끝나면 위젯을 종료하고 같은 경로의 실행 파일을 교체한 후 다시 실행합니다. 교체 또는 재실행 시작에 실패하면 기존 실행 파일을 유지하거나 백업에서 복구합니다. 설정 파일과 자동 실행 등록 경로는 유지됩니다. 실행 파일 폴더에 쓰기 권한이 있어야 하며, 관리자 권한이 필요한 폴더에서는 쓰기 가능한 폴더로 이동해 사용하세요. 이 복구는 설치 과정의 실패를 대상으로 하며 새 버전 실행 후 발생하는 기능 오류까지 자동 감지하지는 않습니다.

자동 업데이트가 없는 이전 실행 파일은 이번 `v1.1.0` 파일로 한 번 직접 교체해야 합니다. 이후 버전부터 위젯에서 업데이트할 수 있습니다. 릴리스에는 바로 실행하는 `CodexUsageWidget.exe`와 자동 업데이트용 `CodexUsageWidget-win-x64.zip`을 제공합니다. 둘 다 .NET 8 Desktop Runtime이 필요합니다.

초기화 문구는 글자 크기와 길이에 맞춰 표시 영역을 확보합니다. 투명도 창은 슬라이더와 자동 실행 체크박스를 자동으로 세로 배치해 겹침을 방지합니다.

소스에서 실행 파일을 만들려면 .NET 8 SDK가 필요합니다.

```powershell
dotnet publish -c Release -r win-x64 --self-contained false -p:PublishSingleFile=true -p:DebugType=None -o obj/publish
Copy-Item obj/publish/CodexUsageWidget.exe . -Force
```

레이아웃 회귀 검증은 연결된 모니터, 한도 1개/2개 표시, 확대된 글꼴에서 초기화 문구와 체크박스의 크기·겹침을 확인합니다. 검증 중 사용자 설정 파일은 백업한 뒤 복원합니다.

```powershell
dotnet run --project tests/LayoutVerification.csproj -c Release
```

Tibo 예고의 분류·원문 검증·중복 방지·요청 제한·설정 저장 검증과 공개 API 연결 확인:

```powershell
dotnet run --project tests/LayoutVerification.csproj -c Release -- --tibo --live
```

업데이트 검증은 가짜 GitHub CLI와 별도 임시 설치 경로를 사용합니다. 동의·거절 창, 버전·해시·ZIP 경로 검증, 잠긴 파일 교체·재실행, 설치 실패 시 복구를 검사하며 사용자 설정을 백업·복원합니다.

```powershell
dotnet build tests/fixtures/FakeGh.csproj -c Release
dotnet run --project tests/LayoutVerification.csproj -c Release -- --updates
```

다음 버전을 배포할 때는 프로젝트의 `Version`을 올리고 게시한 단일 EXE만 ZIP에 넣어야 합니다. `v{Version}` 태그의 정식 GitHub 릴리스에 고정 파일명 `CodexUsageWidget-win-x64.zip`으로 첨부하세요. 초안·시험판과 현재보다 낮거나 같은 버전은 업데이트 대상에서 제외합니다. GitHub가 제공하는 ZIP 자산의 `digest`가 없으면 설치하지 않습니다.
