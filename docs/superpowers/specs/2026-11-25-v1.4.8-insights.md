# v1.4.8 사용량 인사이트 명세

## 목표

기존 3분 갱신 데이터를 활용해 사용량 추세를 로컬에서 보여주고, 알림 기준을 사용자가 조절하며, 메모리·갱신·UIA·app-server 상태를 진단할 수 있도록 한다.

## 기능 요구사항

### 1. 사용량 히스토리·그래프

- 성공적인 Codex·OpenCode Go 갱신마다 UTC 시각, 서비스, 구간, 잔여량, 리셋 시각을 로컬에 기록한다.
- 기본 보관 기간은 30일이며, 외부 서버로 전송하지 않는다.
- 24시간·7일·30일 범위와 서비스·구간을 선택해 추세 그래프를 본다.
- 리셋 시각이 바뀌면 선을 끊어 이전 주기와 새 주기를 연결하지 않는다.
- 손상된 기록 줄은 건너뛰고, 오래된 기록은 정리한다.
- 기록은 API 키나 인증 정보를 포함하지 않는다.

### 2. 알림 정책

- Codex 5시간·주간, OpenCode Go 5시간·주간·월간 각각에 대해 알림 사용 여부, 경고 임계값, 위험 임계값, 반복 간격을 설정한다.
- 기본값은 경고 30%, 위험 10%, 반복 간격 0분(반복 없음)으로 기존 동작을 유지한다.
- 방해 금지 시간대를 설정하면 해당 시간에는 알림을 보류하고, 시간대 종료 후 조건이 계속되면 알린다.
- 기존 알림 이력과 레거시 키는 유지한다.
- 정책 변경과 알림 이력 갱신은 설정 저장 성공 후에만 확정한다. 저장 실패 시 이전 상태로 롤백한다.

### 3. 성능 진단·로그

- 성공적인 갱신마다 WorkingSet, Private Bytes, 스레드 수, 핸들 수, GC 힙 크기와 갱신 소요 시간을 로컬에 기록한다.
- TaskbarBadge의 최근 UIA 조회 시간과 codex app-server 시작·재시작 이벤트를 기록한다.
- 기본 보관 기간은 7일이며, 진단 창에서 현재 값과 최근 추세를 확인한다.
- 로그에는 API 키·암호문·요청 헤더를 기록하지 않는다.

### 4. 조회 안정성

- OpenCode Go 요청은 헤더와 본문을 포함해 전체 15초 timeout을 적용한다.
- 응답 본문은 스트리밍으로 읽어 실제 누적 바이트 262144바이트를 초과하면 거부한다.
- `Content-Length`이 없거나 실제보다 작아도 크기 제한을 우회할 수 없다.

## 비목표

- 클라우드 동기화, 외부 그래프 라이브러리 추가, Rust 이전, 전체 UI 재설계는 이번 범위에서 제외한다.

## 데이터 위치

- 설정: `%LOCALAPPDATA%\CodexUsageWidget\settings.json`
- 히스토리: `%LOCALAPPDATA%\CodexUsageWidget\history-YYYYMMDD.jsonl`
- 진단: `%LOCALAPPDATA%\CodexUsageWidget\diagnostics-YYYYMMDD.jsonl`
