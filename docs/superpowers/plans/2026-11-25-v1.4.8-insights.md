# v1.4.8 사용량 인사이트 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 로컬 사용량 히스토리 그래프, 구간별 알림 정책, 성능 진단 로그를 추가하고 OpenCode Go 조회의 timeout·응답 크기 제한을 보완해 v1.4.8로 배포한다.

**Architecture:** `Program.cs`는 기존 UI·조회 흐름에서 새 모듈을 호출만 하고, 기록·정책 계산·진단 수집은 작은 파일로 분리한다. 새 설정·기록·진단 창은 `GlassForm` 기반의 별도 `Form`으로 만들어 메인 위젯의 크기를 늘리지 않는다. 외부 패키지 없이 .NET 8 WinForms와 `System.Text.Json`만 사용한다.

**Tech Stack:** C#, .NET 8 Windows Forms, WPF/UIA 참조, JSONL, System.Drawing

**Spec:** `docs/superpowers/specs/2026-11-25-v1.4.8-insights.md`

## Global Constraints

- 모든 사용자 문구는 한국어로 한다.
- Codex·OpenCode Go 기존 3분 갱신과 서비스별 실패 격리를 유지한다.
- OpenCode Go 키가 없거나 인증되지 않으면 Go 목록을 숨긴다.
- API 키·암호문·인증 헤더는 히스토리·진단 로그에 저장하지 않는다.
- 새 외부 NuGet 패키지를 추가하지 않는다.
- 기본 임계값은 경고 30%, 위험 10%, 반복 0분으로 유지한다.
- 히스토리 30일, 진단 7일, Go 응답 262144바이트, Go 전체 timeout 15초를 적용한다.
- 배포 버전은 `1.4.8`, 태그는 `v1.4.8`로 한다.

## Review Focus

- 지연되거나 `Content-Length`이 없는 Go 본문도 15초 안에 종료하고 실제 바이트 상한을 지키는가 — Task 1의 스트리밍·지연 응답 테스트.
- 리셋 경계를 넘는 히스토리가 한 선으로 연결되거나 오래된·손상된 기록이 그래프를 깨뜨리지 않는가 — Task 2의 리셋 분할·보관·손상 테스트.
- 방해 금지 종료 직후·반복 간격 도달·설정 저장 실패가 기존 알림 이력을 잃거나 중복 알림을 만들지 않는가 — Task 3의 정책 경계·롤백 테스트.
- 진단 로그가 비밀값을 저장하거나 장기간 파일·메모리를 무한 증가시키지 않는가 — Task 4의 7일 정리·비밀값 부재 테스트.
- 폼 직접 `Dispose`, 설정 컬렉션 `null`, 지연된 키 저장 응답이 리소스·상태를 망가뜨리지 않는가 — Task 5의 수명·정규화 테스트.

### Task 1: OpenCode Go 요청 경계 보완

**Files:**
- Modify: `OpenCodeGoUsage.cs`
- Test: `tests/GoVerification.cs`
- Modify: `Program.cs`

**Interfaces:**
- Produces: `OpenCodeGoUsage.ReadAsync(HttpClient client, string apiKey, CancellationToken cancellationToken = default)`
- Produces: `OpenCodeGoUsage.ReadAsync(HttpClient client, string apiKey, TimeSpan timeout, CancellationToken cancellationToken = default)`
- Consumes: 기존 `OpenCodeGoAuthException`, `OpenCodeGoRateLimitException`, `InvalidDataException`

- [ ] **Step 1: 크기 우회·지연 본문 실패 테스트 추가**
  - `Content-Length`이 없는 스트림으로 `MaximumResponseSize + 1` 바이트를 반환하는 핸들러를 추가하고 `InvalidDataException`을 기대한다.
  - 헤더만 반환하고 본문을 무기한 대기시키는 핸들러에 짧은 timeout을 넘겨 `OperationCanceledException`을 기대한다.
- [ ] **Step 2: 테스트가 이유대로 실패하는지 확인**
  - Run: `dotnet run --project tests/LayoutVerification.csproj -c Release -- --go`
  - Expected: 초과 응답이 파싱되거나 지연 응답이 timeout 없이 대기해 실패.
- [ ] **Step 3: 스트리밍 크기 검사·전체 timeout 구현**
  - `ResponseHeadersRead` 후 `ReadAsStreamAsync`로 8KB씩 읽고 실제 누적 바이트를 검사한다.
  - 연결된 cancellation token을 본문 읽기까지 전달한다.
- [ ] **Step 4: Go 테스트와 전체 빌드 확인**
  - Run: `dotnet run --project tests/LayoutVerification.csproj -c Release -- --go`
  - Expected: 기존 31개와 새 경계 테스트가 모두 통과.
- [ ] **Step 5: 커밋**
  - `git add OpenCodeGoUsage.cs Program.cs tests/GoVerification.cs`
  - `git commit -m "fix: bound OpenCode Go response reads"`
